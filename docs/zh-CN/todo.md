# 待办清单

这个文档用于记录 Java Review Graph 在当前 MVP 之后最值得继续推进的工作。
优先顺序是：先提升分析准确性，再处理可维护性，最后补性能和体验。

## P0：分析准确性

- [ ] 接入真正的 JDT 绑定解析，覆盖类型和方法。
  完成标准：常见 Maven Java 项目里的跨文件类型引用，优先通过 binding 解析，而不是仅靠名称兜底。
- [ ] 支持跨类型的方法调用解析。
  完成标准：方法调用边可以正确指向其他类中的目标方法，而不再只局限于同类匹配。
- [ ] 完善 import、package 和全限定名处理。
  完成标准：`uses_type` 关系里的 unresolved 情况在正常项目中显著减少。
- [ ] 给关系补充置信度和回退原因。
  完成标准：每条非平凡关系都能说明它来自精确 binding，还是来自回退推断。

## P0：增量索引可靠性

- [x] 为每个快照持久化实际变更文件集合。
  完成标准：前端和 API 都能看到某次增量快照到底是基于哪些文件构建出来的。
- [x] 记录本次索引为什么走全量或增量。
  完成标准：像构建文件变化、缺少基线快照这类 fallback 原因可见。
- [x] 显式处理 rename 和 move 场景。
  完成标准：文件重命名不再只表现为“无解释的删除加新增”。
- [ ] 让影响传播深度可配置。
  完成标准：默认仍保持一跳，但可以显式开启更深层传播。

## P1：后端重构

- [ ] 拆分 `ProjectIndexService`。
  建议拆成：Git 变更收集、增量规划、快照组装、diff 计算、快照元数据处理。
- [ ] 把图构建逻辑和传输层、持久化层解耦。
  完成标准：不经过 controller 也能独立测试索引核心流程。
- [x] 增加快照诊断 API。
  完成标准：前端可以直接查询 diff 基线、变更文件、fallback 原因和重建范围。

## P1：前端重构

- [ ] 按功能拆分 `App.tsx`。
  建议拆成：项目工作区、快照面板、变更面板、图谱工作区、设置模块。
- [ ] 按职责拆分 `GraphCanvas.tsx`。
  建议拆成：布局、视口状态、节点交互、边渲染、场景持久化。
- [ ] 收敛图谱状态流转。
  完成标准：全屏、过滤视图、焦点切换、重置视图这些行为由可预测的统一状态驱动，而不是散落在各处的事件处理。

## P1：图谱性能和可用性

- [ ] 降低前端主包体积。
  完成标准：图谱重模块和设置模块支持懒加载，主 chunk 体积警告下降或消失。
- [ ] 为长快照列表和变更列表增加虚拟化。
  完成标准：历史记录很多时仍然保持流畅。
- [ ] 优化大图场景下的渲染策略。
  可选方向：渐进式展示节点、边简化、分阶段布局、视口内渲染。
- [x] 增加索引诊断面板。
  完成标准：用户不看日志也能知道快照来源、变更文件、fallback 原因和重建范围。

## P1：作品展示功能

- [ ] 增加 Git 变更集 review 分析。
  完成标准：给定一个 commit 区间或 diff 基线后，可以产出变更符号、受影响符号和 review 摘要。
- [ ] 增加可解释的变更风险评分。
  完成标准：低 / 中 / 高风险等级可以由已存储信号和图谱证据推导出来。
- [ ] 增加符号路径和影响追踪查询。
  完成标准：UI 可以展示 review 相关符号之间的依赖路径或调用路径。
- [ ] 增加 Markdown 审查报告导出。
  完成标准：一次分析运行后可以导出一份可分享的 review 摘要。
- [ ] 增加历史快照对比。
  完成标准：任意两个快照可以并排展示符号和关系的演进变化。
- [ ] 增加 AI 辅助 review 解释。
  完成标准：基于图谱证据自动生成可读的 review 说明和测试建议。

## P2：SQLite 和持久化

- [x] 检查并补齐高频查询索引。
  已覆盖当前图查询和增量快照维护涉及的快照、源文件、符号、关系等主要读取路径。
- [ ] 启用或验证 WAL 模式和批量写入。
  完成标准：项目规模变大后，索引写入和界面读取仍然稳定。
- [ ] 增加快照保留和清理工具。
  完成标准：可以安全清理旧快照、孤儿数据和陈旧布局状态。

## P2：测试覆盖

- [ ] 为 Git 驱动的增量索引增加集成测试。
  覆盖 committed only、uncommitted only、混合变更、untracked 文件和无基线快照场景。
- [x] 增加 rename、delete 和构建文件触发全量回退的测试。
- [ ] 增加关键 review 流程的前端冒烟测试。
  重点覆盖项目导入、不支持语言拦截、图谱过滤、全屏模式、快照重命名和快照删除。

## P2：文档同步

- [x] 更新 `roadmap.md`，补齐当前桌面端方向和 MVP 之后的展示型里程碑。
- [ ] 补一份故障排查文档。
  重点覆盖不支持项目导入、后端连接失败、增量回退原因和图谱可读性问题。
- [ ] 保持 API 和索引文档与实现一致。

## 建议实施顺序

1. 分析准确性
2. 增量诊断和 rename 处理
3. 后端重构
4. 前端重构
5. 性能和持久化
6. 更完整的测试覆盖
7. 文档补齐
