# 前端设计

## 目的

`apps/web` 负责承载代码图谱的 review 体验。

## 主要页面

### 项目初始化页

- 选择或查看已导入项目
- 查看快照状态

### Review 主页面

- 左侧：变更符号列表和过滤器
- 中间：图画布
- 右侧：详情面板

### 快照历史页

- 查看历史索引结果
- 重新打开旧的 review 上下文

## 图交互规则

- 默认视图只展示类型级节点
- 点击某个类型后，展开该类型内部的方法
- 默认不要展开不相关类型的方法
- 选中变更符号后，应当自动居中并高亮
- 边和节点样式要能清楚表达变更状态

## 可视状态模型

- `added`
  绿色强调
- `modified_api`
  红色强调
- `modified_impl`
  橙色或琥珀色强调
- `deleted`
  弱化或虚线处理
- `impacted`
  次级告警强调

## 数据需求

前端期望 API 已经区分好：

- 类图节点和边
- 单个选中类的方法图
- 符号详情数据
- 变更原因和影响原因

## MVP 规则

第一版界面优先保证可读性，而不是信息密度。
如果图谱过大，前端应当主动缩小范围，而不是把所有内容都画出来。

## 当前实现状态

当前前端已经提供：

- 项目导入表单
- 已导入项目列表
- 全量和增量索引控制
- 快照列表
- 类图视图
- 选中类后的方法图展开
- 变更列表和当前选择详情面板

当前实现说明：

- 图渲染目前是轻量的 SVG 加绝对定位画布，还没有接 Cytoscape
- 本地开发时，Vite 会把 `/api` 代理到 `http://localhost:8080`
- 当前 UI 已经接到现有后端接口和 SQLite 快照数据
- 右侧检查面板现在还可以执行 change-set review、展示确定性的风险与优先目标，并导出 Markdown 报告
- change-set review 面板现在还会展示直接传播路径，帮助解释为什么某个变更会影响下游 review 目标
- 同一个面板现在还会给出确定性的测试关注建议，让演示可以自然落到具体回归或集成测试目标
